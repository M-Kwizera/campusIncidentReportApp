# Firebase Security Rules for Campus Incident Reporting App

## Firestore Rules

Copy these rules to your Firebase Console under Project Settings > Database > Rules:

```javascript
rules_version = '2';
service cloud.firestore {
  // Enable debug mode during development (remove in production)
  match /databases/{database}/documents {
    
    // Incidents Collection
    match /incidents/{incidentId} {
      // Allow authenticated users to read all incidents
      allow read: if request.auth != null;
      
      // Only allow students and staff to create new incidents with pending status
      allow create:
        if request.auth != null && 
           isUserAuthenticated(request.auth) &&
           request.resource.data.status == "pending";
      
      // Allow updates only for incidents that are still being processed
      allow update:
        if request.auth != null && 
           isUserAuthenticated(request.auth) && 
           (request.resource.data.status in ["pending", "in_progress"]);
      
      // Prevent deletion of incidents
      allow delete: if false;
    }
    
    // Users Collection (synced from Firebase Auth)
    match /users/{userId} {
      // Allow authenticated users to read their own data
      allow read, write:
        if request.auth != null && 
           request.auth.uid == userId;
    }
  }
}

// Helper function to check if user is authenticated
function isUserAuthenticated(auth) {
  return auth.token != null && auth.token.emailVerified == true;
}
```

## Storage Rules

Copy these rules to your Firebase Console under Project Settings > Storage > Rules:

```javascript
rules_version = '2';
service firebase.storage {
  match /b/{bucket}/o {
    // Allow authenticated users to upload incident images
    match /incidents/{userId}/{timestamp}/{fileName} {
      allow write:
        if request.auth != null && 
           request.auth.uid == userId &&
           request.resource.size < 5 * 1024 * 1024; // Max 5MB
      
      // Allow authenticated users to read their own images
      allow read:
        if request.auth != null && 
           request.auth.uid == userId;
    }
    
    // Deny all access to other paths
    match /- {
      allow read, write: if false;
    }
  }
}
```

## Firebase Authentication Configuration

### Enable Custom Claims for Roles

1. Go to Firebase Console > Authentication > Settings
2. Navigate to "Sign-in method"
3. Click on "Custom claims"
4. Add custom claim `role` with values:
   - `student`: For regular student accounts
   - `staff`: For staff/admin accounts

### Email Pattern Validation (Optional)

For production, consider implementing email pattern validation:
- Students: Any email format
- Staff: Must contain 'campus', 'admin', or 'staff' in domain

## Testing the Security Rules

1. **Test Student Account**
   - Create student account
   - Verify can create incidents
   - Verify cannot update incident status

2. **Test Staff Account**
   - Create staff account (email with 'staff' in domain)
   - Verify can create and update incidents
   - Verify access to dashboard

3. **Test Unauthorized Access**
   - Try to access incidents without auth
   - Verify proper error messages
   - Verify no data leakage

## Production Considerations

1. **Remove Debug Mode**: Set `allow read: if true;` to specific auth checks
2. **Implement Rate Limiting**: Prevent abuse of the reporting system
3. **Audit Logging**: Enable Firestore audit logs for security monitoring
4. **Regular Updates**: Keep Firebase rules updated as features evolve
5. **Monitoring**: Set up alerts for unusual activity patterns

## Troubleshooting Security Issues

### Issue: Unauthorized Access to Incidents
**Solution**: Check that `allow read` has proper auth conditions.

### Issue: Students Can Update Status
**Solution**: Verify security rules only allow staff to update status.

### Issue: Image Upload Failures
**Solution**: Ensure storage rules allow write with proper size limits.
