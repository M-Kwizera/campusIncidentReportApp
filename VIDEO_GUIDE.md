# Video Demonstration Guide

## Objective
Create a 7-10 minute video demonstrating the Campus Incident Reporting App's main workflows.

## Video Structure (Target: 8 minutes)

### Section 1: Introduction (0:00 - 1:00)
**Duration**: 60 seconds

**Content:**
- Brief overview of the app and its purpose
- Screen recording setup (use OBS Studio or similar)
- Introduce both user roles (student and staff)

**Tips:**
- Keep it professional and concise
- Mention the problem being solved
- State what will be demonstrated

---

### Section 2: Student Account Setup & Login (1:00 - 2:30)
**Duration**: 90 seconds

**Content:**
1. **Registration (30 seconds)**
   - Open app splash screen
   - Navigate to auth screen
   - Click "Register"
   - Fill in form:
     - Name: "John Student"
     - Email: "john@university.edu"
     - Password: "Password123!"
   - Show successful registration
   
2. **Login (30 seconds)**
   - Clear credentials or create new account
   - Switch to login mode
   - Enter email and password
   - Show successful login
   
3. **Home Screen (30 seconds)**
   - Show bottom navigation tabs
   - Demonstrate tab switching
   - Mention role detection based on email domain

**Screenshots/Notes:**
- Capture form validation errors
- Show loading states during authentication

---

### Section 3: Submitting an Incident Report (2:30 - 4:00)
**Duration**: 90 seconds

**Content:**
1. **Navigate to Report Screen (15 seconds)**
   - Tap bottom navigation "Report" tab
   
2. **Fill Incident Form (45 seconds)**
   - Enter title: "Broken AC Unit in Room 304"
   - Select category: "Broken Facilities"
   - Enter detailed description:
     "The air conditioning unit in room 304 is completely broken. Students are complaining about the heat, especially during exam season. Please check and repair as soon as possible."
   - Click "Attach Photo"
   - Select an image from gallery
   - Show preview of attached image
   
3. **Submit Report (15 seconds)**
   - Tap "Submit Report" button
   - Show loading indicator
   - Verify success message
   - Navigate back to incidents list
   
4. **View Submitted Incident (15 seconds)**
   - Show new incident in the list
   - Open incident detail view
   - Display all information including image

**Screenshots/Notes:**
- Capture form validation (required fields)
- Show category dropdown options
- Demonstrate image selection

---

### Section 4: Browsing and Filtering Incidents (4:00 - 5:30)
**Duration**: 90 seconds

**Content:**
1. **Incidents List View (20 seconds)**
   - Show incidents list screen
   - Mention filter options at top
   
2. **Filter by Category (30 seconds)**
   - Select dropdown menu
   - Change from "All" to different categories:
     - "Water Shortage"
     - "Electricity Outage"
     - "Safety Concern"
   - Show filtered results updating
   
3. **Search Functionality (20 seconds)**
   - Click search icon or enter search text
   - Search for specific incidents
   - Show search results
   
4. **Pull-to-Refresh (20 seconds)**
   - Demonstrate pull-down gesture
   - Show loading state
   - Simulate new incident appearing

**Screenshots/Notes:**
- Capture different category colors
- Show status badges on cards
- Demonstrate real-time updates

---

### Section 5: Staff Account Setup & Login (5:30 - 7:00)
**Duration**: 90 seconds

**Content:**
1. **Staff Registration (30 seconds)**
   - Logout from student account
   - Register new staff account:
     - Name: "Campus Manager"
     - Email: "manager@university.edu" or "admin@university.edu"
     - Password: "Admin123!"
   - Show role detection based on email domain
   
2. **Staff Login (30 seconds)**
   - Login with staff credentials
   - Verify dashboard is accessible
   - Note the navigation difference (dashboard tab)
   
3. **Staff Dashboard (30 seconds)**
   - Show all three tabs:
     - "All Incidents"
     - "Pending"
     - "In Progress"
   - Tap on "Pending" tab
   - Show filtered pending incidents

**Screenshots/Notes:**
- Show role-based navigation
- Demonstrate dashboard-specific features
- Note different UI elements

---

### Section 6: Staff Updates Incident Status (7:00 - 8:00)
**Duration**: 60 seconds

**Content:**
1. **Select Incident to Update (20 seconds)**
   - Scroll through pending incidents
   - Select an incident card
   
2. **Update Status Dialog (20 seconds)**
   - Click edit/status button on card
   - Show status dropdown:
     - "pending"
     - "in_progress"
     - "resolved"
     - "closed"
   - Select "in_progress"
   - Confirm the update
   
3. **Verify Status Change (20 seconds)**
   - Check incident list shows updated status
   - Verify color change on status badge
   - Navigate to detail view to confirm

**Screenshots/Notes:**
- Capture status dropdown clearly
- Show before and after states
- Demonstrate real-time updates

---

### Section 7: Conclusion (8:00 - 8:30)
**Duration**: 30 seconds

**Content:**
- Brief summary of demonstrated features
- Mention key benefits:
  - Efficient reporting process
  - Real-time status tracking
  - Role-based access control
  - Intuitive user interface
- Thank viewers for watching

**Tips:**
- Keep it professional
- End with clear call to action (check GitHub repo)

## Recording Setup

### Recommended Tools

1. **Screen Recorder**: OBS Studio (free) or Loom
2. **Audio**: Built-in microphone or external mic
3. **Browser Extension**: Chrome DevTools for browser recording if needed

### Screen Resolution Settings
- Target: 1080p (1920x1080)
- Frame rate: 30fps or 60fps
- Audio quality: Good/High

### Best Practices

1. **Stable Camera/Angle**: Fixed position for consistent recording
2. **Clear Text**: Ensure all text is readable (increase font size if needed)
3. **Smooth Transitions**: Use natural gestures between screens
4. **Professional Voiceover**: Clear, confident narration
5. **No Distractions**: Clean background or use virtual background

---

## Post-Processing

### Video Editing Software
- Adobe Premiere Pro (paid)
- DaVinci Resolve (free/pro)
- CapCut (free)
- iMovie (Mac, free)

### Recommended Edits
1. **Trim unnecessary pauses**
2. **Add captions/subtitles**
3. **Insert keyframes for emphasis**
4. **Smooth out jerky movements**
5. **Add intro/outro graphics**

### Export Settings
- Format: MP4
- Resolution: 1080p
- Codec: H.264
- Bitrate: 5-8 Mbps
- Audio: AAC, 192kbps

## Alternative Recording Methods

### Option 1: Screen Capture Only
Record only the screen without voiceover:
- Add text overlays for key information
- Use arrows or highlights to draw attention
- Keep narration minimal

### Option 2: Dual Camera (Optional)
Split screen with:
- Left: Your face/talking head
- Right: Screen recording
- More engaging but requires more setup

## Checklist Before Recording

- [ ] Test all app features work correctly
- [ ] Create test accounts (student and staff)
- [ ] Prepare demo data (pre-loaded incidents if needed)
- [ ] Check network connection is stable
- [ ] Verify audio recording works
- [ ] Review video script/timeline
- [ ] Ensure good lighting (if using dual camera)
- [ ] Test screen resolution settings
- [ ] Backup project files

---

## Common Mistakes to Avoid

1. **Skipping steps**: Don't rush through important actions
2. **Unclear narration**: Speak at a moderate pace
3. **Poor audio quality**: Check microphone before recording
4. **Technical glitches**: Test recording setup beforehand
5. **Missing key features**: Ensure all required workflows are shown
6. **Confusing navigation**: Don't show too many screens at once
7. **Inconsistent styling**: Maintain uniform font sizes throughout
